xv6中的VirtIO虚拟磁盘驱动机制解析

本文介绍了 xv6 操作系统中 VirtIO 虚拟磁盘驱动的核心原理与实现流程，内容主要包括：

  • 驱动初始化阶段：通过 virtio_disk_init() 完成设备身份验证、特性协商、内存结构初始化以及中断注册。
  • I/O 请求流程：virtio_disk_rw() 构造请求命令、组织描述符链、写入可用队列并通知设备处理；
  • DMA + 中断机制：设备使用 DMA 方式直接读写内存，完成后通过中断回调 virtio_disk_intr() 通知驱动；
  • 通信结构详解：包括 desc 描述符链、avail 可用队列、used 已用队列三大核心数据结构；

适合深入理解 xv6 内核中虚拟磁盘驱动的底层通信机制与 virtio 协议结构。

在 QEMU 虚拟机中运行的 xv6 操作系统，通过 VirtIO 协议 与虚拟磁盘设备进行通信, 使用 MMIO（Memory-Mapped I/O） 将设备寄存器映射到内核地址空间，驱动程序通过访问这些内存地址完成设备的初始化与控制。

例如，启动 QEMU 时添加如下选项来启用 virtio-mmio 磁盘：

1、初始化阶段：virtio_disk_init()

在内核启动早期，驱动需对 virtio 设备进行初始化，步骤包括：

  • 检查设备身份（魔术值、设备 ID、厂商 ID 等）
  • 协商设备特性（只启用驱动支持的功能）
  • 设置页大小
  • 初始化共享内存结构（描述符、可用队列、已用队列）
  • 初始化描述符空闲状态标志
  • 注册virtio_disk_intr()中断回调（在 plic.c 与 trap.c 中完成）

2、一次 I/O 请求的完整流程

在用户进程访问文件或块设备时，内核调用 virtio_disk_rw() 发起磁盘 I/O。其过程如下：

2.1、发起请求（驱动 → 设备）

在 virtio_disk_rw() 中，驱动发起一次磁盘 I/O 请求，主要包含以下步骤：

  1. 分配 3 个空闲描述符：用于构建请求的描述符链（命令头、数据块、状态字节）；
  2. 填写请求内容：
    • 第1个描述符：请求头，包括操作类型（读/写）、扇区号等；
    • 第2个描述符：数据缓冲区地址（供读/写传输）；
    • 第3个描述符：状态字段，用于接收设备完成标志；
  3. 组织描述符链：通过 desc[i].next 字段将这 3 个描述符串联成链；
  4. 更新队列：
    • 将链头索引写入 avail.ring[]；
    • 递增 avail.idx；
  5. 通知设备：通过写入 MMIO 寄存器 QUEUE_NOTIFY，通知设备开始处理请求；
  6. 挂起等待完成：当前进程调用 sleep()，等待设备中断通知 I/O 完成。

2.2、设备执行（DMA）

设备采用 DMA（Direct Memory Access） 方式访问内存。根据这组操作符链，直接读/写内核中的缓冲区（如 b->data），无需 CPU 协助。

2.3、中断响应回调（设备 → 驱动）

设备完成请求后会触发中断，驱动中的 virtio_disk_intr() 被调用，执行以下操作：

  1. **读取 used.idx**：判断设备是否有新完成的请求；
  2. **遍历 used.ring[]**：获取设备返回的已完成请求（通过描述符链头部索引 id）；
  3. 检查状态字段：确认状态字节为 0 表示成功；
  4. 标记请求完成：将 buf->disk = 0，表示对应缓冲区已准备就绪；
  5. 唤醒等待进程：通过 wakeup() 恢复之前挂起等待该 I/O 的进程；
  6. 回收描述符链：释放对应的 3 个描述符，供下次使用。

3、VirtIO 通信结构概览

一次 I/O 请求的执行流程，主要依赖下列三类结构：

(1) 描述符（desc）

(2)可用队列 avail（驱动 → 设备）

驱动通过 ring[] 提交请求，递增 idx 表示新请求就绪。

(3)已用队列 used（设备 → 驱动）

设备执行完成后，在 used.ring[] 中写入链头索引，驱动比较 used.idx 判断哪些请求完成。
