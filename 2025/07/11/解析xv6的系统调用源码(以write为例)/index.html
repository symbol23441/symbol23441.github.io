解析xv6的系统调用源码(以write为例)

用户程序在执行文件读写、进程控制、内存分配等操作时，往往需要访问底层硬件资源。但为了保障系统安全与稳定，操作系统必须禁止用户程序直接访问这些敏感资源。否则，一旦出现错误或恶意行为，可能导致内核崩溃或数据泄露。为此，操作系统引入了系统调用机制（System Call），使用户程序通过标准接口（如 write()）以一种受控、安全的方式请求内核服务，所有关键操作都由内核代表执行。

系统调用的底层依赖陷入机制（Trap Mechanism）：用户程序通过指令（如 RISC-V 的 ecall）触发硬件陷入，CPU 自动保存上下文、切换特权级，并跳转至内核中的 trap 处理函数。操作完成后，再通过 sret 指令安全地返回用户态。详见xv6 trap篇

本篇博客以 xv6 操作系统中经典的 write() 系统调用为例，结合源码逐步解析系统调用从用户态陷入内核、内核完成服务、再安全返回用户态的整个流程，帮助理解操作系统如何借助硬件支持，安全地调度和管理资源。

2、ecall 触发 trap 硬件机制

执行 ecall 后，RISC-V 硬件会自动执行以下操作：

  • 切换 CPU 到 S-mode（管理模式）
  • 清除中断使能位（SIE），防止中断打断 trap handler
  • 保存当前 PC 到 sepc
  • 将 stvec 中的地址加载到 PC，作为 trap 入口

此时，CPU 开始执行 stvec 指定的地址。对于来自用户空间的 trap，xv6 设置 stvec = uservec代码地址（ trampoline.S）

3、trampoline.S .uservec

trampoline.S是一段特别的代码，形象的称为蹦床代码。xv6 通过将 trampoline.S 这一页同时映射到用户页表和内核页表的相同虚拟地址（最高页），本质是保证用户页表与内核页表切换的过程中，程序能顺利进行。

在 .uservec 中：

  1. 使用 sscratch 拿到当前进程的 trapframe
  2. 保存所有通用寄存器到 trapframe 中
  3. 加载 trapframe 中的内核页表地址，切换为内核页表
  4. 清除 TLB（sfence.vma）
  5. 无条件跳转到 usertrap()（C 函数）

4、usertrap：进入内核处理 trap

usertrap() 位于 trap.c，用于处理来自用户空间的 trap。主要步骤：

  1. 检查是否是用户态陷入（SPP == 0），否则 panic
  2. 将 stvec 切换为 kernelvec，用于后续内核态 trap
  3. 保存 sepc 到当前进程的 trapframe->epc
  4. 检查 scause 是否为 8（系统调用）
  5. 如果是系统调用：
    • 跳过 ecall 指令（epc += 4）
    • 开中断（intr_on()）
    • 调用 syscall() 处理系统调用

5、syscall 分发系统调用

syscall() 会根据 a7 中的系统调用号，从函数指针数组中找到对应的处理函数。

对于 SYS_write，对应的是 sys_write()，定义在 sysfile.c 中。

7、返回用户空间：usertrapret()

完成系统调用后，从 usertrap() 调用 usertrapret() 返回用户空间。

usertrapret() 的任务是：

  • 关中断
  • 设置 stvec = uservec（为下次陷入做准备）
  • 设置 sstatus 中的 SPP = 0（恢复用户态）
  • 设置 SPIE = 1（返回后开启中断）
  • 设置 sepc 为用户代码下一条指令
  • 跳转到 trampoline.S 的 .userret

8、trampoline.S：.userret 恢复用户态

.userret 的职责是：

  1. 切换回用户页表（写入 satp）
  2. 清除 TLB快表
  3. 恢复寄存器
  4. 保存trapframe地址到sscratch
  5. 执行 sret，回到用户态，继续执行 ecall 后的代码

用户最终在 a0 中得到系统调用的返回值。

9、sret 硬件机制

sret（Supervisor Return）是 RISC-V 中的一个特权指令，用于从当前陷入的 S-mode（管理模式）返回到之前的特权级（通常是 U-mode，即用户态）。它的执行涉及多个关键寄存器的操作。

sret 的作用：

当执行 sret 时，RISC-V 硬件会执行以下步骤：

  1. 从 sepc 恢复程序计数器（PC）
    → 即从 sepc 载入原本用户程序中断/异常发生前的地址，跳回用户空间执行。
  2. 根据 sstatus.SPP 设置下一模式：
    • 如果 SPP = 0：从 S-mode 返回到 U-mode（用户模式）
    • 如果 SPP = 1：从 S-mode 返回到 S-mode（如内核 trap 嵌套时）
  3. 恢复中断使能位：
    • sstatus.SIE ← sstatus.SPIE
    • 然后清除 SPIE 位（SPIE ← 0）
      → 这允许返回后立刻开启中断，并准备好下一次 sret 的保存

10、返回到用户态

汇编usys.S ret,返回到用户程序继续执行。
